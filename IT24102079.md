# IT24102079 – Order History & Bid System

## Assigned Functionalities
* View previous orders
* Order status tracking (Processing, Shipped, Out for Delivery, Delivered)
* Reorder option from past orders
* Search and filter order history
* Download invoices from past orders
* Place bids on selected products
* View current highest bid
* Bid closing timer
* Winner notification (SMS / Email)

## Codebase Attribution & Methods

### `com.app.store.controller.UserOrderController.java`
* `viewOrderHistory()` - Iterates the user's historical purchases to view previous orders mapped to live Order status tracking enums.
* `reorderItems()` - Maps past catalog line items directly back into the live `CartService` for instantaneous reorder processing.
* `viewInvoice()` - Dynamically generates formatted, downloadable invoices from past orders via the `/{orderId}/invoice` mapping.

### `user/orders.html`
* Houses the custom Javascript DOM engine directly implementing the Search and filter order history requirement by reading typed strings or selected Enums to manipulate active CSS classes. 

### `com.app.store.service.impl.AuctionServiceImpl.java`
* `placeBid()` - Secures concurrent database writes allowing sellers to place bids on selected products safely.
* Contains advanced algorithmic checks verifying mathematical thresholds (e.g., ensuring a new bid aggressively supersedes the view current highest bid properties).
* Built the `autoCloseAuctions()` scheduled execution acting as the rigorous bid closing timer. When an end date breaches or an Expected Price ceiling is shattered, this system locks the `Auction` state natively.

### `com.app.store.controller.SellerAuctionController.java` & `seller/active-auction-detail.html`
* Exposes the B2B routes managing active bids.
* Drives the aesthetic UX layout projecting the View current highest bid metrics dynamically on-screen.

### `com.app.store.service.impl.MessagingServiceImpl.java` & `com.app.store.service.EmailService.java`
* `dispatchSystemMessage()` / `sendOrderConfirmation()` - Leveraged by `AuctionServiceImpl` upon closing to dispatch the winner notification (SMS / Email) routing the victory receipt and payment instructions to the winning bidder.

### Frontend & UI Templates
* `templates/user/orders.html` - The comprehensive dashboard for customers to view previous orders, live order status tracking lines, and quick reorder options. It also hosts the DOM-based search and filter order history mechanism.
* `templates/user/invoice.html` - The raw, printable layout accessed via the "Download invoices" capability.
* `templates/seller/active-auctions.html` & `templates/seller/active-auction-detail.html` - The high-stakes B2B marketplaces enabling users to place bids on selected products and view the live-updating current highest bid scalars until the closing timer trips.

## Workflow Explanation
The Order History and Bid System workflow focuses on complex historical retention and competitive marketplace mechanics. After submitting an order, the user accesses `UserOrderController.viewOrderHistory()` to track shipping stages, securely download invoices, or trigger `reorderItems()` to instantly rebuild a previous checkout basket. If a user needs to quickly locate a specific package, they utilize the DOM Javascript search and filter tool embedded within the history page. Simultaneously, the framework supports a robust B2B bidding environment. Verified sellers can interact with `SellerAuctionController` to monitor active biddings. By calling `AuctionServiceImpl.placeBid()`, a competitor attempts to breach the current highest bid scalar. If successful, they hold the lead until the `@Scheduled` bid closing timer inevitably trips. Once automatically locked, the system engages the Messaging and Email protocols to trigger a winner notification alerting the buyer of their victory.
